# Blender visual upgrade — Light the River

## Direction

Create an original moonlit river diorama in Blender: faceted mountains, a curved
turquoise river, a small stage with a modeled digital piano, and warm lanterns.
Use a rendered scene in the existing journey panel, preserving the readable HTML
piano and note lanes. This is the hybrid first release proposed in the discussion;
a real-time orbitable 3D stage remains a future experiment, not a requirement here.

## Implementation sequence

1. Locate and verify Blender in the sibling `3d_astra/.tools` directory. Run it
   headlessly; keep all new scene sources, scripts and output in Piano_tutor.
2. Build a reproducible procedural scene with original meshes/materials, camera,
   night lighting and subtle glow. Save an editable `.blend` plus desktop/mobile PNGs.
3. Inspect the render and adjust composition so scenery and piano are recognizable
   in a shallow banner. Keep note lanes and interactive keys unobstructed.
4. Integrate the render with responsive image selection, a CSS gradient fallback,
   existing progress lanterns, and three modes: Cinematic, Calm, Off.
5. Cinematic adds gentle light motion and a brief glow for correctly played notes
   and completed phrases. Calm is still; reduced-motion users get still visuals
   regardless of the requested mode. Default to Calm on narrow screens.
6. Persist the preference defensively. Decorative imagery has empty alt text;
   controls and textual progress remain accessible. Hide optional art in Off mode.
7. Test preference validation, reactions, reduced motion, existing game tests and
   production build. Inspect desktop and mobile UI. Review and fix any issues.
8. Commit and push via SSH, verify the Pages workflow and public assets.

## Asset budget and ownership

- No external textures or copyrighted models. Blender geometry is generated by
  `scripts/render-river-stage.py`; `.blend` is retained for manual art editing.
- Target desktop image under 1 MB, mobile under 350 KB. Prefer pre-rendered images
  over adding a GPU renderer or increasing runtime JavaScript dependencies.
- The interactive HTML piano retains its geometry and input events; improve its
  cabinet/rim lighting with CSS rather than replacing working controls with a photo.
- New art stays behind gameplay. No strobing, camera shake, mandatory animation,
  or scoring changes. Loading failures keep the existing river fallback visible.
